Arcod is a language and a compiler for agent-built services. You write one .arc file — types, operations, errors, rules, effects, bindings — and get routes, adapters, an OpenAPI contract, a UI, tests, deploy manifests and prompts a small local model can actually follow. No library shopping, no drift between the model and the code.

CHECKED, NOT GUESSED

Rights are declared, not hand-written

auth op, roles: and owner: id become a guard in the runtime: 401 for anonymous, 403 for the wrong role or somebody else's record, 404 when the record is gone. A046–A049 catch a guard with no actor source or a role outside the service vocabulary.

LIVE, NOT POLLED

One page, a websocket, zero idle traffic

The service publishes an event after every mutation and the page reads state. A slide reaches the phones in 13–17 ms, and an idle room sends nothing at all; polling every 3 s would keep every phone talking all session.

why another tool

The model and the code are two descriptions of one thing.
They drift.

Arcod removes the second description. What cannot be checked — is not allowed to be guessed.

No library shopping

The model names a capability (kv, sql, llm, stream), the environment names a provider. The compiler knows the adapter and refuses a provider that does not implement the capability.

Prompts a 7B model can follow

One prompt per operation, derived from the contract: 66–109 tokens instead of a service description. Constant rules live in the system prompt, so the model never re-invents the framework.

Unresolved is a failure

If a step cannot be derived from effects and type shapes, generation stops with unresolved instead of quietly inventing code. Unhandled errors, unused bindings and unknown clauses are diagnostics, not surprises.

examples/onetimemessage/main.arc
service OneTimeMessage : http {
  uses store: kv(ttl: 999s)
  uses uuid: ids

  contract {
    public op create(body: Body) -> MessageId {
      route: "POST /api/messages"
      effects: store.set, uuid.new
      errors: Invalid
      on error Invalid: body != null
    }

    public op read(id: MessageId) -> Body {
      route: "GET /api/messages/:id"
      errors: NotFound, Gone
    }
  }

  rules {
    invariant read.at_most_once: once(read, by: id)
    atomic read { get; del }
  }
}

what you get

Everything the service needs, derived from one source.

Not snippets to paste — artifacts that run, and that the compiler keeps honest.

Records, not blobs

A record type is a store. rules { unique Task.title } is a claim the adapter keeps: the second task with that title is the declared Conflict, not a 500. io.find takes where, order, limit and a keyset cursor, so a page does not shift under inserts.

Migrations from the model

arcod migrate turns record types into typed tables — uuid as CHAR(36), unique rules as UNIQUE KEY — with a checksummed changelog the service applies on boot. Re-runs are no-ops; an edited migration refuses to start.

Observable without a stack

Every service logs one JSON access line per request, echoes and propagates x-request-id, and serves /metrics in Prometheus format — RPS, latency histogram, errors, in-flight and capability calls. Timeouts come from ARCod_TIMEOUT_MS.

Contracts that become behaviour

atomic read { get; del } becomes a Lua script; once(read, by: id) becomes a tombstone key returning Gone. budget { concurrency: 8 } becomes a 503 limiter.

UIs without a frontend decision

Forms from public operations, layout: chat for dialogue, layout: presentation for decks: a join code, a QR encoder vendored into the page, and slide changes pushed to every phone.

Someone else's service, still typed

external service Ledger { ... } gives a remote client typed by a partial contract; the address comes from the environment, never from the body.

A contract others can read

arcod openapi prints OpenAPI 3.1 on stdout: paths from route, schemas from types, status codes from the same error mapping the runtime uses, and the model's examples as named examples. No server, no host, no provider in the document.

Deploy as a declaration

deploy docker | aws | yandex | kubernetes produces compose or a deploy.<env>.json manifest with "executed": false — no credentials, no API calls behind your back.

honesty

v0.1 is a vertical slice.

A compiler you cannot trust is worse than no compiler, so the gaps are documented and diagnosed, not hidden.

What does not work yet

  • Scaffold without bodies knows only create and read; with --impl any operation is accepted.
  • OLAP, metrics, secrets and friends are provisioned in compose but have no effect signatures; Kafka and RabbitMQ provision a queue the adapter cannot speak — bind queue to Redis.
  • find is a scan with a filter, not a query planner: one entity namespace matched in memory. Fine for thousands of rows, not millions; schema-aware SQL tables and indexes come next. A unique claim also outlives a TTL-expired record until the record is removed.
  • Migrations create the typed tables, but the v0.1 runtime still writes records as blobs in arcod_kv — the typed schema is the schema of record until the runtime moves onto it.
  • Workflows are parsed, described and validated — no runner is generated (W022); a job runs only when it declares an on: queue consumer (W017).
  • Streams and queues are in-process until you bind them to Redis; only then do replicas share events. OpenAPI has no securitySchemes yet.
  • JavaScript only. PHP, Go and Python would be separate emitters.

What that buys you

  • Every claim above has a diagnostic code, a test, or a note in the README.
  • No silent fallbacks: an underivable step fails with unresolved.
  • No cloud calls: the default model endpoint is local and a remote one is refused without --allow-remote.
  • No hidden dependencies: the emitted service and page are single files, including the RESP client and the QR encoder.

terminal
$ git clone git@github.com:chubakur/arcod.git
$ cd arcod && npm link
$ cd examples/quiz && arcod make . --impl
$ arcod run --impl
